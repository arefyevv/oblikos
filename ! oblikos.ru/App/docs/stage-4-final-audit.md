# Этап 4: финальный UI/UX polishing и технический аудит

Дата: 2 октября 2026 года. **Этап 4 — ГОТОВ.**

## Найдено и исправлено

- Пустая память показывала две одинаковые CTA. Теперь при count=0 кнопка только внутри empty state. При наличии записей кнопка только в заголовке, включая пустой результат фильтра.
- Внутренняя область растягивалась до 1000 px, меню было далеко от текста. Memory ограничена 780 px, как существующая область настроек; общий detail layout сохранён. Список остаётся лёгкими строками с разделителями.
- Success оставался постоянно. Все успешные операции используют общий таймер 4 секунды; новый action/filter также очищает сообщение. После заключительной полировки success отображается компактным уведомлением с галочкой внизу экрана, вне потока документа; пустая строка обратной связи больше не занимает место. Исчезновение success не сдвигает список. Ошибки не исчезают по таймеру, данные и ввод остаются.
- Создание под активным фильтром всегда предлагало «Факт». Теперь начальный тип соответствует фильтру, пользователь может выбрать любой другой.
- Кнопка edit совпадала с create. Теперь заголовок «Редактировать воспоминание», submit «Сохранить изменения»; create сохраняет «Сохранить воспоминание».
- Фокус возвращался сразу после закрытия modal, до завершения обновления списка. Теперь возврат ждёт окончания transition: при исчезновении строки после смены типа/удаления фокус переходит на единственную видимую CTA. При удалении последней записи это CTA empty state.
- Дополнены E2E для ранее непроверенных filtered mutations, длительности сообщений, последнего удаления, длинного текста/меню и всех состояний на четырёх ширинах.

Предыдущая правка симметричных hover-отступов «Редактировать» в обзорных карточках сохранена.

## Состояния и визуальное поведение

Empty state: «Память пока пуста», пояснение и одна центральная CTA. При выбранном пустом типе и существующих записях: «Нет воспоминаний этого типа», фильтр и верхняя CTA. Счётчик показывает общее число записей Character, независимо от типа.

Строка: тип, человекочитаемая важность, спокойная надпись «Закреплено», меню «•••»; ниже основной текст и «Обновлено DD.MM.YYYY». Длинные слова переносятся; метаданные и дата второстепенные. Текст ограничен 75ch, вся внутренняя область 780 px. В заключительной полировке основной текст увеличен до существующего --text-base (14 px), метаданные сохранены компактными и приглушёнными; pinned использует тот же вторичный цвет. Верхний отступ empty state уменьшен до 48 px, на mobile до 32 px.

Форма и список используют одинаковые 5 labels важности. Дата форматируется `ru-RU`, timezone Europe/Moscow. Сортировка сохранена: pinned DESC → importance DESC → updatedAt DESC → id ASC. Pin/unpin и порядок после reload проверены.

Фильтр остаётся в URL. Create другого типа не нарушает выбранный фильтр, edit со сменой типа убирает строку из результата, delete обновляет total и filtered state. Все 7 типов доступны. Modal сохраняет native overlay, первоначальный focus, Tab/Shift+Tab trap, Escape/Cancel и подтверждаемое удаление. Во время сохранения поля/submit отключены; Escape не закрывает занятую форму. Ошибки сети не дают ложный success. Повтор после потери успешного ответа не создаёт вторую запись.

## Технический аудит

Архитектура, Prisma schema и migrations **не изменены**. Проверены MemoryEntry relation/FK, defaults, enum, два query index, CHECK constraints и Prisma Client.

Server Actions по-прежнему не принимают identity/workspaceId. Текущий Workspace определяется сервером; membership, Character workspace/deletedAt и принадлежность записи повторно проверяются внутри транзакции. Запросы изменения включают тот же scope. Подмена Character/MemoryEntry, чужой Workspace, участие в двух Workspace с выбранным scope, anonymous request, invalid IDs, revoked membership и soft-deleted Character проверены. Дополнена явная negative-проверка UNPIN чужой записи.

Duplicate Character оставляет count=0. Retrieval helper остаётся server-only: current Workspace, Character, сортировка, default limit=30, maximum=50, структурированные записи. UI query ограничен 100 строками. AI, prompt generation, embeddings, pgvector и внешние API отсутствуют.
