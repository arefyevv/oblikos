# Создание персонажа по фото

На странице `/characters/new` загрузка фото находится на шаге «Внешность», после идентичности. Отдельного переключателя способов создания нет: можно описать внешность вручную, загрузить 1–10 фото или совместить оба способа. Пользователь выбирает основной снимок и при желании заполняет внешность через AI. Фото сохраняются в существующей приватной медиатеке, основное становится обложкой.

Для созданного персонажа загрузка также доступна в `/characters/[id]/appearance`. Новые снимки и описание сохраняются атомарно кнопкой «Сохранить изменения». Первый снимок нового набора становится основным; старые референсы сохраняются в медиатеке. Общий лимит — 10 неудалённых загруженных референсов. Повтор отправки одного набора не создаёт дубликаты. Для архивного персонажа загрузка запрещена.

## Форматы и хранение

- JPG, PNG, WebP, до 10 МиБ на исходное фото; до 40 мегапикселей.
- Браузер оптимизирует фото до JPEG, 1600 пикселей по длинной стороне и не более 1 МиБ. Сервер повторно проверяет сигнатуру, декодирование и размер, нормализует ориентацию и удаляет метаданные.
- Профиль, Appearance, Personality и все MediaAsset создаются одной транзакцией с повторной проверкой членства в workspace. UUID запроса защищает от повторного создания при повторе отправки. Неиспользованные файлы удаляются; при недоступной БД файлы сохраняются до проверки, чтобы не удалить результат с потерянным подтверждением commit.
- Фото имеют `provider=user-upload`, `model=reference-photo`. Изменений схемы БД и миграций нет. Доступ — через существующий защищённый `/api/media/[id]`.
- Генерация изображений использует основной образ первым, затем остальные загруженные референсы, суммарно до 10. Удалённые фото исключаются; доступ перепроверяется до вызова AI и перед commit.

## AI

Описание внешности: существующий Responses API с несколькими `input_image`, `store=false` и проверяемым JSON schema. Используются `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_VISION_MODEL` (при отсутствии — `OPENAI_MODEL`). Модель должна поддерживать изображения и структурированный ответ. Источник формата: [OpenAI Images and vision](https://developers.openai.com/api/docs/guides/images-vision).

Описание внешности можно редактировать и заполнять вручную при недоступном провайдере. Анализ использует существующие ограничения текстовых AI-запросов; отправка фото также ограничена по пользователю. Имя, возраст, характер, ниша и голос задаются пользователем, а не выводятся из фото.

Редактирование изображений передаёт один файл при одном референсе и массив при нескольких. Требуется `OPENAI_IMAGE_REFERENCE_SUPPORTED=true` и модель/совместимый провайдер, поддерживающий несколько входных изображений. При отключённой поддержке референсов существующая генерация по текстовому описанию сохраняется.

## Файлы

Новые: `photo-limits.ts`, `photo-upload.tsx`, `photo-operations.ts`, `photo-actions.ts` в `src/features/characters`; интеграционный тест `tests/character-photos.integration.test.ts`; браузерный тест `tests/e2e/character-photos.spec.ts`.

Изменены: форма и операции персонажей, AI provider, image provider, операции медиатеки, CSS, Next config, пример окружения, шаблон nginx, тест транспорта изображений и существующий offline AI hook.

## Развёртывание

Next Server Actions ограничены 12 МиБ на запрос. В шаблоне `deploy/nginx.conf` установлен соответствующий `client_max_body_size 12m`. Перед включением функции на существующем production-хостинге применить этот лимит в действующем блоке nginx для `app.oblikos.ru`, проверить `nginx -t` и выполнить reload. Штатная отправка релиза приложения сама не изменяет nginx. Сохранить существующий порт upstream и остальные настройки. Серверные фотографии остаются в настроенном постоянном `MEDIA_STORAGE_DIR` между релизами.

## Проверки

`npm run typecheck`, `npm run lint`, `npm run build`.

`node --conditions=react-server --import=tsx --test tests/character-photos.integration.test.ts tests/characters.integration.test.ts tests/media.integration.test.ts`.

PowerShell: `$env:EMAIL_PROVIDER='development'; npx playwright test tests/e2e/character-photos.spec.ts`. AI в браузерных тестах работает через существующий offline hook: реальные платные вызовы не выполняются. Фикстуры изолированы и очищаются, пользовательские данные сохраняются.
