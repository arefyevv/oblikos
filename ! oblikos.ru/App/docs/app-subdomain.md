# Сервис на app.oblikos.ru

Согласованная схема: `https://oblikos.ru` — лендинг,
`https://app.oblikos.ru` — сервис, регистрация и вход.
Кнопки лендинга: «Войти» → `https://app.oblikos.ru/login`,
«Начать работу» → `https://app.oblikos.ru/register`.

## Перенос действующей установки

1. В DNS добавить запись A: имя `app`, значение `159.194.211.8`.
   Дождаться разрешения `app.oblikos.ru` в этот IP. Основную запись домена
   до готовности лендинга сохранять. Не добавлять AAAA без настроенного IPv6.
2. Обновить разрешённые адреса сайта и callbacks в используемых OAuth-приложениях:
   `https://app.oblikos.ru/api/auth/callback/yandex` и
   `https://app.oblikos.ru/api/auth/callback/vk`.
3. Подготовить отдельный HTTP server block для `app.oblikos.ru` и ACME challenge,
   выпустить сертификат на поддомен. Старый HTTPS-конфиг сохранять до проверки.
4. Сделать защищённые резервные копии текущего Nginx-конфига и production.env.
   Установить обновлённый `deploy/nginx.conf` для поддомена, выполнить `nginx -t`.
   Директива `limit_req_zone` должна быть объявлена только один раз, если старый
   и новый server blocks временно работают вместе.
5. В `/etc/oblikos/production.env` изменить только
   `NEXTAUTH_URL=https://app.oblikos.ru`. Сохранить AUTH_SECRET, БД, media и SMTP.
   Опубликовать release с новым `src/config/app.ts`, перезапустить приложение
   и перезагрузить Nginx после успешной проверки конфигурации.
6. Проверить HTTPS `/api/health`, регистрацию и вход, адреса писем подтверждения
   и восстановления, OAuth и доступ к сохранённым данным. Cookies ограничены
   хостом: на поддомене пользователям потребуется повторный вход.
7. После проверки разместить лендинг на основном домене. При необходимости
   сохранить редиректы старых маршрутов сервиса на соответствующие маршруты
   `app.oblikos.ru`; не перенаправлять корень основного домена после запуска лендинга.

`npm run deploy` обновляет исходники, но не DNS, сертификаты, Nginx или production.env.
Локальный `.env` остаётся с `NEXTAUTH_URL=http://localhost:3000`.
Почта `noreply@oblikos.ru` сохраняет основной домен.

## Состояние на 4 октября 2026 года

Настройки и инструкции переведены на поддомен, release опубликован на VPS.
В REG.RU добавлена A-запись `app → 159.194.211.8`.
Для `app.oblikos.ru` выпущен сертификат Let's Encrypt с автоматическим продлением.
Nginx и production.env переключены на `https://app.oblikos.ru`;
проверка HTTPS health подтверждает работу приложения, БД и media storage.
На VPS приложение слушает `127.0.0.1:3001`, фактический Nginx использует этот порт.
Основной домен временно перенаправляет все маршруты на сервис кодом 302.
При публикации лендинга заменить этот временный redirect его конфигурацией.
Резервные копии настроек находятся на VPS в защищённом каталоге
`/etc/oblikos/domain-backup-20261004-095733`.
