## Hailuo: расширение защищённой ссылки — 12.10.2026

С разрешения пользователя production `AI_VIDEO_PER_DAY` повышен с 5 до 10;
конфигурация сохранена перед изменением, web и worker перезапущены.
Пятисекундный тест с лимитом 110,50 ₽:
`d5bb99d9-e251-4884-84dd-0b8b87b34ef4` — HTTP 400 до выдачи providerJobId.
Причина: Hailuo проверяет расширение пути URL и требует .mp4 или .mov,
а прежняя защищённая ссылка заканчивалась подписью.

Локально ссылки получили .mp4 / .png. Проверка HMAC, срока, владельца,
статуса задания и отзыва ссылок сохранена. Старые ссылки работают;
несоответствие расширения типу подписанного файла отклоняется. Проверено
20 тестами performance, TypeScript и ESLint. Требуется обычный деплой.
Повторная отправка теста не выполнена.

## Диагностика отказа запуска — 12.10.2026

Повторная попытка `25db6430-d5f2-4317-9611-e7d4491e247c` показала
HTTP 400 / InvalidParameter: входной видеореференс Seedance Mini должен иметь
не менее 407696 пикселей в кадре. Добавлена проверка сохранённого MP4 при
расчёте стоимости, постановке в очередь и перед отправкой worker. Маленький
исходник вызывает пользовательскую ошибку `seedance_source_resolution`
с примерами 480×854 / 720×1280, без запроса генерации. Проверяются именно
размеры исходника, а не выбранный выходной формат. Старые загрузки тоже
проверяются; миграция БД не требуется.

В production попытка Seedance `53ec9844-ab65-4db6-9972-8fb714f9a6d8`
завершилась `FAILED / invalid`, без `providerJobId`. Старый обработчик удалял
тело HTTP-ошибки, поэтому её подробности восстановить невозможно.

Новый обработчик пишет в журнал worker строку
`Reference video provider rejected request`: ID задания, модель, HTTP-статус,
`x-request-id` (или `request-id`), код, параметр и очищенное сообщение ошибки.
Чтение тела ограничено 32 КиБ, сообщение — 800 символами. Ключ, ссылки,
data URI и совпадающий текст запроса скрываются; сырые тела запросов/ответов
не записываются. В пользовательскую ошибку подробности провайдера не попадают.
Автоматический повтор POST не добавлен.

После деплоя читать журнал:

```powershell
ssh root@159.194.211.8 'journalctl -u oblikos-video-worker --since "15 minutes ago" --no-pager'
```

Изменение само не повторяет неудавшееся задание. Для получения новой ошибки
нужна отдельная разрешённая пользователем попытка; при принятии API она платная.

## Seedance 2.0 Mini — 12.10.2026

В перенос исполнения добавлена `seedance-2.0-mini` через существующий AITUNNEL.
Локальная `.env` переключена на эту модель; production в этой задаче не менялся.
Вход — одно фото (включая общий снимок группы) + MP4 H.264, **4–15 секунд**.
Видео автоматически не сокращается: для теста на 5 секунд нужен исходник на 5 секунд.
Выход — **720p**: 720×1280 / 1280×720 / 720×720.

Каталог AITUNNEL от 12.10.2026: вертикальный и горизонтальный формат —
12,852 ₽/сек, квадратный — 7,22925 ₽/сек. Оценка округляет длительность вверх,
а общую сумму — вверх до четырёх знаков (точность поля БД), без предварительного
округления тарифа. 9:16: 5 сек = 64,26 ₽, 15 сек = 192,78 ₽.
Смета содержит модель; изменение модели или цены требует нового расчёта.
Старые PROCESSING-задания Hailuo проверяются через сохранённую модель.

```dotenv
MOTION_VIDEO_PROVIDER=aitunnel
MOTION_VIDEO_MODEL=seedance-2.0-mini
SEEDANCE_PRICE_RUB_PER_SECOND=12.852
SEEDANCE_SQUARE_PRICE_RUB_PER_SECOND=7.22925
```

Отдельные ключи и аккаунты не нужны. Генерация и проверка результата идут через
AITUNNEL, а исходная песня при выбранной опции возвращается существующим FFmpeg.
Передача фото + видео подтверждена контрактными тестами и публичным каталогом;
качество трёх котят и точная синхронизация пения **не проверены** реальной генерацией.

Для production после обычного `npm run deploy` и проверенной резервной копии:

```powershell
ssh root@159.194.211.8 "python3 /opt/oblikos/current/scripts/configure-reference-video.py --model seedance-2.0-mini"
```

Скрипт сверяет актуальные тарифы и параметры, требует пустую очередь активных
референсных заданий, сохраняет конфигурацию и перезапускает web/worker.
При ошибке возвращает предыдущие настройки. Платных генераций сам не создаёт.
Без `--model` сохраняется прежний сценарий настройки Hailuo.
`npm run video:check -- --require-empty` проверяет выбранную модель без генерации.
Проверки реализации: 17 unit/integration тестов, браузерный сценарий формы
на 1440/390/320 px, ESLint, TypeScript, production build и сверка публичного
каталога прошли. Локальный worker запущен после проверки пустой очереди.
Платные запросы в этой задаче не отправлялись.

## Группа героев и оригинальная песня — 09.10.2026

В «Анимация → Повторить исполнение» добавлены «Кто повторяет видео → Несколько
героев с фото · эксперимент», обязательное описание «Кто кого заменяет» и
«Сохранить оригинальную песню и звук». Все герои должны быть на одном фото.
Групповая инструкция сохраняется в параметрах и fingerprint задания, участвует
в смете и блокирует повторное платное создание с изменёнными ролями. В групповом
промпте больше нет прежнего принудительного `One character` и противоречащего
общему фото профиля одного человека.

Роли передаются как текстовая инструкция Hailuo 3. Это **не** маски объектов,
детекция/трекинг или подтверждённая независимая замена трёх актёров. Животная
анатомия, точная хореография и подпевание нескольких морд остаются экспериментом;
отдельный multi-face lip-sync API не подключён. Поддержка video+image проверена по
[документации AITUNNEL](https://aitunnel.ru/docs/videos) и публичному каталогу.

Оригинальный звук возвращает серверный FFmpeg (`ffmpeg-static`, exact 5.3.0).
Сгенерированное видео и аудио исходного MP4 копируются без перекодирования;
новый ролик обрезается до длительности исходника без изменения скорости.
Перед отправкой платного задания проверяются бинарник и наличие звука у исходника;
после сборки проверяются H.264, размеры, длительность и наличие аудио.
FFmpeg работает только с приватными временными файлами, без shell, с разрешёнными
протоколами file/pipe, лимитами времени и размера; файлы удаляются в finally.
Неподдерживаемый для копирования аудиокодек вызывает ошибку сборки, не молчаливую
подмену песни. Повтор сборки использует прежний providerJobId и не запускает новую
платную генерацию. Старая опция fal остаётся провайдерской.

Проверки: 15 performance-тестов, 18 регрессионных Avatar/video-тестов, браузерный
сценарий с группой, ролями, исходным звуком и размерами 320/390/1440; lint и build.
Отдельный тест сверяет AAC-данные исходника и результата побайтово.
Пользовательские файлы: `E:\1.mp4` (14,234 сек, 360×640, есть аудио) и фото трёх
котят. Смета: 15 × 22,10 = 331,50 ₽. На этапе подготовки платный тест был
заблокирован: автоматическая проверка потребовала подтверждение суммы и отправки этих
двух файлов в AITUNNEL. UUID подготовленной попытки:
`2531a88e-e5b1-42c5-bb5f-8ddcf7b124a4`; очередь пуста, POST не отправлен.

Позднее Виктор явно разрешил тест за 331,50 ₽. Первый локальный receipt был
остановлен лимитом до POST: mock-тесты загрязнили global-day (90 при лимите 20).
Квота восстановлена по единственному реальному receipt до 1; лимиты и срок окна
не менялись. Video/performance integration-тесты теперь используют случайный
AUTH_SECRET в своём процессе и не расходуют квоту обычного приложения.
Следующая операция `acfb03e1-c723-4c6b-a827-3df0ae3612b1` была принята AITUNNEL,
но провайдер не скачал собственную временную data-URI-ссылку: `media download
failed (HTTP 206)`. API подтвердил `usage.cost_rub=0`.

Для production добавлены подписанные ссылки `/api/ai-inputs/[token]`:
HMAC-SHA256 с отдельным purpose, конкретный job + вид файла, срок до 3 часов.
Выдаются только сервером для AITUNNEL performance. Маршрут повторно проверяет
активность задания, участника workspace, персонажа и принадлежность конкретного
исходника/изображения; после READY/FAILED ссылки отзываются. Он не принимает
произвольные пути, URL или asset ID от скачивающего клиента. Ответ всегда полный
200 (включая Range), no-store, без cookie и без раскрытия URL в UI. Обычные медиа
остаются за авторизацией. Локальный localhost не доступен модели; там остаётся

## Текущий основной провайдер: AITUNNEL

Перенос исполнения теперь по умолчанию использует **AITUNNEL / Hailuo 3**, существующий
`AITUNNEL_API_KEY`; отдельный fal-аккаунт не требуется. Публичный каталог и документация
проверены 09.10.2026, снимок: `artifacts/video-reference-catalog-latest.json`.
Вход: приватное фото + MP4 H.264, **5–15 сек**, до 1080p / 30 МиБ. Выход:
**2K**, 9:16 / 16:9 / 1:1. Тариф из каталога: **22,10 ₽/сек**. Для расчёта
длительность округляется вверх; 6,027 сек оцениваются как 7 × 22,10 = 154,70 ₽.
Оценка не заменяет итоговый биллинг провайдера.

Hailuo получает `input_references` с `video_url` + `image_url`, точный размер 2K,
длительность и `generate_audio=true`. Исходники отправляются как data URI; AITUNNEL
конвертирует их во временные HTTPS-ссылки на своей стороне. В форме нет фиктивных
переключателей Kling: ориентация и отдельная стадия липсинка не заявлены.
Звук создаёт модель; при включённом сохранении песни он заменяется исходной
дорожкой локально (см. раздел выше). Синхронизация рта не гарантирована.
Качество переноса движений и кошачьей анатомии требует проверки на реальных материалах.

```dotenv
MOTION_VIDEO_PROVIDER=aitunnel
MOTION_PRICE_RUB_PER_SECOND=22.1
AVATAR_PRICE_RUB_PER_SECOND=8.5
REFERENCE_VIDEO_WORKER_ENABLED=true
```

Цены сверять с актуальным публичным каталогом. Для прочих режимов ключи прежние.
`npm run video:check` проверяет настройки, каталог и очередь без платных запросов.
После деплоя и проверенной резервной копии серверный запуск:

```bash
sudo python3 /opt/oblikos/current/scripts/configure-reference-video.py
```

Скрипт определяет Node из web service, сохраняет конфигурацию в защищённый каталог,
сверяет цены/возможности каталога, требует пустую очередь новых референсных заданий,
устанавливает worker systemd и перезапускает web/worker. При сбое возвращает
предыдущие настройки. Сам генерацию не запускает. Новая миграция не требуется.
Deploy перезапускает активный worker вместе с web; backup останавливает оба процесса.

`FAL_KEY`, `MOTION_PRICE_USD_PER_SECOND`, 3–30 сек / orientation=image до 10 сек.
Сохранённые операции проверяются через исходного провайдера, переключение не создаёт
новую платную операцию. Историческое описание fal и первоначальной реализации ниже

## Границы и ограничения приложения

- Аудио: один голос, WAV PCM или MP3, до 60 сек и 10 МиБ. Определяются реальные контейнер, кодек, число каналов и длительность; MIME браузера не считается доказательством типа.
- Исполнение: MP4 с H.264, 3–30 сек, до 1920×1080 пикселей и 30 МиБ. Для orientation=image — до 10 сек. Это ограничения первой версии приложения; максимальные размеры загрузок самого провайдера отдельно не заявляются.
- Фото: JPEG/PNG/WebP до 20 МиБ, проверка сигнатуры и декодирования существующим Sharp. Загружается как отдельный образ в медиатеку, без изменения основного образа.
- Для танца нужен полный рост с видимыми конечностями; для жестов — руки/лапы в кадре. Основной портрет автоматически не подставляется. Выбор фото для аудио и для исполнения хранится отдельно.
- В Motion Control кадр определяется изображением; нет фиктивного выбора выходного формата или разрешения. Есть только подтверждённые ориентация и сохранение исходного звука. Последнее не означает гарантированный липсинк.
- Исходники приватные, доступны только загрузившему пользователю в его рабочем пространстве и только 24 часа. Не публикуются и не отправляются в клиент как подписанные URL. Провайдер получает data URI по HTTPS, без внешнего открытия локального хранилища. Правила хранения на стороне провайдеров определяются их собственными условиями; 24 часа относится к нашему хранилищу.
- Результат — приватный MP4 в существующей медиатеке. Проверяются контейнер, размеры и длительность; для аудиорежима обязательна звуковая дорожка. Отклонение длительности от исходника более 1 сек отклоняется. Это техническая проверка, не доказательство визуального липсинка.

```powershell

```

## Идемпотентность и ошибки

- UUID + fingerprint запроса защищают повторную отправку; исходники, режим, параметры, модель, пользователь, провайдер и смета хранятся в MediaGeneration.
- До POST ставится durable submissionStartedAt атомарным updateMany. Конкурирующий worker не отправляет вторую операцию.
- Обрыв после POST, неизвестный ответ или crash между отправкой и сохранением providerJobId не повторяет POST. Задание получает ambiguous; возможную внешнюю операцию проверяет администратор. Сетевого «exactly once» без идемпотентности провайдера обещать нельзя.
- ID провайдера сохраняется; проверка статуса и сохранение результата защищены lease и транзакцией. Сбой хранилища повторяет только GET/download, без новой генерации.
- Ограничение — 360 проверок / 3 часа, backoff ошибок до 5 минут. Не показывается вымышленный процент готовности. После deadline providerJobId остаётся для ручной сверки; это не отмена операции у провайдера и не обещание возврата средств.
- Нет многостадийного платного конвейера: загруженное аудио не вызывает TTS; Motion Control не запускает вторую стадию липсинка.
- API не принимает произвольные исходные URL. Результаты AITUNNEL скачиваются с фиксированного API; fal — только HTTPS `fal.media` / одноуровневые поддомены, без авторизации CDN и перенаправлений. Неожиданный CDN блокируется.

## Воспроизводимая проверка качества

Скрипт `video:smoke` по умолчанию только проверяет локальные файлы и смету. Он ничего не скачивает и не обращается к платному API. Нужны собственные или разрешённые материалы:

1. `tests/manual/talking-cat.png` + `tests/manual/talking-cat.wav`: кошачья морда видна, 4–6 сек речи одного голоса, умеренные движения головы.
2. `tests/manual/gesture-character.png` + `tests/manual/gesture-reference.mp4`: антропоморфный персонаж с видимыми лапами/телом и 4–8 сек собственной жестикуляции. Исходный звук можно сохранить, но это не проверенный липсинк.

Эти ручные файлы не приложены: разрешённых материалов для оценки животных пользователь пока не предоставил. Автотестовые заливки/тишина и существующий MP4 проверяют транспорт и UI, не художественное качество.

```powershell
npm run video:smoke -- --case talking-cat --image tests/manual/talking-cat.png --audio tests/manual/talking-cat.wav
npm run video:smoke -- --case gesture-character --image tests/manual/gesture-character.png --video tests/manual/gesture-reference.mp4
```

Только после отдельного разрешения на платный тест добавить `--allow-paid --user USER_UUID --workspace WORKSPACE_UUID --character CHARACTER_UUID`. UUID берутся у авторизованного локального аккаунта и его персонажа. Для повторной проверки добавить `--request REQUEST_UUID` из первого запуска: это возобновляет receipt, не запускает успешную операцию заново. Скрипт сохраняет `artifacts/performance-live-REQUEST_UUID.json` без ключей и ссылок провайдера; готовый ролик — в приватной медиатеке.

Для каждого результата вручную отметить PASS/FAIL и таймкоды: внешность/окрас; рот в такт фонемам; отсутствие человеческого лица; лапы и тело; соответствие жестов/танца; неизменность предметов; длительность/звук. В receipt все визуальные пункты изначально NOT_REVIEWED. Для motion-only mouthSync не считать выполненным автоматически.
