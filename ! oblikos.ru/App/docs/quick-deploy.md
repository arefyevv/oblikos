# Обновление одной командой с Windows

Откройте PowerShell в `E:\Projects\Oblik OS\! oblikos.ru\App`:

```powershell
npm run deploy
```

OpenSSH подключается к `root@159.194.211.8:22`. При первом подключении проверьте
отпечаток SSH-сервера с панелью VPS. Введите SSH-пароль при запросе (символы
не отображаются). Пароль не записывается в проект. С SSH-ключом запросов пароля нет.

Скрипт собирает архив исходников без `.env*`, зависимостей, сгенерированного Prisma
client и локальных данных. Загружает новый release, использует Node из systemd unit,
устанавливает зависимости и собирает сайт от пользователя службы. Сайт продолжает
работать на предыдущей версии до переключения `current`. После restart проверяется
локальный `/api/health` на порту из systemd unit. При неуспехе current возвращается
на предыдущую версию и служба перезапускается. Предыдущие releases сохраняются;
автоматической очистки нет. Не загружайте одновременно файлы через FileZilla.

Перед распаковкой серверный скрипт проверяет минимум 2 ГБ свободного места.
Ошибка `ENOSPC: no space left on device` означает заполненный диск; сообщение
`ssh.exe failed (exit 1)` в конце лишь сообщает о завершении удалённой команды.
Проверить место: `ssh root@159.194.211.8 'df -h /opt/oblikos'`.
Освобождать можно восстанавливаемые `node_modules` и `.next` старых неактивных
релизов, сохраняя текущую версию и свежие релизы для быстрого отката.
Базу, media и серверные настройки при такой очистке не удалять.

На сервере должны быть bash, tar, diff, flock, curl, runuser, Node 24/npm и настроенная
служба oblikos с symlink `/opt/oblikos/current`, абсолютным Node ExecStart и
`/etc/oblikos/production.env`. Скрипт не меняет env, systemd, Nginx, DNS, БД или media.
Если папка prisma отличается, скрипт проверяет неизменность прежних миграций,
статус миграций и соответствие серверной БД новой схеме. Неприменённые миграции
или расхождение схемы останавливают обновление. Миграции применяются отдельно,
после проверенной резервной копии; сам deploy БД не меняет.
Первую реальную публикацию проверьте на сайте.

Другой адрес/порт:

```powershell
.\scripts\deploy.ps1 -Server root@example.com -Port 22
```

Проверка архива без подключения к серверу:

```powershell
.\scripts\deploy.ps1 -Server root@159.194.211.8 -PrepareOnly
```

Команда покажет путь временного архива и его содержимое. Удалите архив после проверки.

## Публичный блог на основном домене

На действующем VPS Next.js использует порт **3001**, а основной домен
обслуживает Vite-лендинг. После первого deploy блога подключите Nginx:

```powershell
Get-Content -Raw .\scripts\enable-blog-routing.py | ssh root@159.194.211.8 'python3 -'
```

Скрипт читает фактический порт службы, проверяет наличие блога, сохраняет
резервные копии конфигурации, устанавливает `/etc/nginx/snippets/oblikos-blog.conf`,
включает его в HTTPS-конфигурацию основного домена и добавляет 301 с поддомена.
Перед reload выполняется `nginx -t`; при ошибке возвращаются исходные файлы.
Python 3 нужен только для этой настройки. На 6 октября 2026 года она уже применена.

Для обычного обновления статей достаточно `npm run deploy`: маршрутизация
сохраняется в `/etc/nginx`. Повторное подключение требуется при смене порта
или восстановлении конфигурации. Порт 3000 в шаблоне нельзя использовать
без сверки с текущей службой; скрипт подставляет действующий порт автоматически.
